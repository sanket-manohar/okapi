06 · Permissions
37 permissions, one enum.

        
Each value maps to the right Android or iOS API for the device's OS version. Where a permission doesn't exist, Okapi returns notApplicable so your code can simply proceed.

      

        
        
        
        
        
      

      

    


    
    

      
07 · Install
Running in three steps.

        
The PDF guide walks through every step with screenshots, written so a first-time Flutter developer can follow it.

      

        
1
Add the package
Run this in your app's folder.
flutter pub add okapi

        
2
Declare what you use
Or let dart run okapi:sync write it for you.
<uses-permission
  android:name="android.permission.CAMERA" />

<key>NSCameraUsageDescription</key>
<string>Scan QR codes to pay.</string>

        
3
Ask
Okapi runs the whole flow and returns a clear result.
final r = await Okapi.ask(
  context,
  OkapiPermission.camera,
);
if (r.isGranted) openScanner();

I built Okapi after rewriting the same permission screens, edge cases and "why is it stuck?" fixes in app after app. It's the package I wanted: accurate on real devices, private by design, and good-looking out of the box.

          
Every decision in Okapi comes from a real failure in a real app, from the Android dialog that gets dismissed and is mistaken for "don't ask again", to reminders that never ring on phones with aggressive battery savers.

          

            
01Accuracy over assumptionsOkapi compares Android's rationale signal before and after every request instead of guessing.

            
02Privacy by defaultNo network calls, no analytics, no declared permissions. Your app asks only for what it needs.

            
03Design that earns a yesClear explanations before the one-shot system dialog, so users understand and agree.
